# Avoid Issue Cache & Best Practices
# Use this file to context-load the AI before refactoring to prevent regressions.

---

### 1. GENERAL / ARCHITECTURE
- **PRESERVE FEATURES:** Never remove existing functionality during optimization. If replacing a loop or system, ensure the new implementation covers all previous use cases (e.g., selection highlighting, grid toggling).
- **SOURCE OF TRUTH:** The `engineInstance` (ECS + SceneGraph) is the source of truth. React components (`SceneView`, `Inspector`) should sync *from* the engine, not drive it directly.
- **TYPESCRIPT STRICTNESS:** Respect strict type boundaries. Do not pass `Float32Array` where `ArrayBuffer` is expected without proper casting or union types in helper signatures.

---

### 2. NODE GRAPH (`components/NodeGraph.tsx`)
- **AVOID RELATIVE UNITS:** Do NOT use CSS classes (e.g., `h-9`, `p-2`, `rem`) for node headers or ports.
  - **Reason:** DOM element sizes must exactly match the `GraphMath` constants used to draw SVG wires.
  - **Solution:** Use explicit pixel values in `style={{ height: HEADER_HEIGHT, ... }}`.
- **PERFORMANCE:** Avoid `array.find()` in render loops or drag handlers. Use `Map<string, Node>` for O(1) lookups.
- **ACCESSIBILITY:** All inputs (`<input>`) and interactive elements must have `aria-label` or `title`. Missing these causes Severity 8 build failures.
- **DEBOUNCING:** Debounce the `compileGraph` call. Do not run heavy graph logic on every `mousemove` event.

---

### 3. RENDERER (`services/renderers/WebGLRenderer.ts`)
- **VIEWPORT SYNC:** Always check and set `gl.viewport` at the start of the `render()` frame. Do not rely solely on a `resize` event listener, as it may miss the initial layout pass.
- **BUFFER BINDING:** Explicitly `bindBuffer` immediately before calling `vertexAttribPointer`. Do not assume the buffer is still bound from previous operations.
- **TEXTURE SAFETY:** When using `sampler2DArray` (WebGL2), you MUST explicitly set `TEXTURE_WRAP_S` and `TEXTURE_WRAP_T`. Failing to do so causes black textures on some drivers.
- **CULLING RISKS:** Be cautious with `gl.enable(gl.CULL_FACE)`. If geometry disappears, disable culling first to rule out winding order mismatches.
- **BUFFER ORPHANING:** When updating instance data, call `gl.bufferData(..., gl.DYNAMIC_DRAW)` to orphan the buffer before `gl.bufferSubData`. This prevents GPU pipeline stalls.

---

### 4. SCENE VIEW & CAMERA (`components/SceneView.tsx`)
- **3D PANNING:** Do not use 2D screen X/Y offsets for camera panning.
  - **Solution:** Calculate the camera's local "Right" and "Up" vectors and apply movement along those vectors to ensure panning follows the camera's orientation.
- **LINTER COMPLIANCE:** Ensure all toolbar buttons (Icons) have `title` and `aria-label` attributes.

---

### 5. SCENE GRAPH (`services/SceneGraph.ts`)
- **ITERATION OVER RECURSION:** Avoid recursive functions for `updateWorldMatrix` or `setDirty`. Use a stack-based `while` loop to prevent stack overflow crashes in deep hierarchies (100+ entities).

---

### 6. COMMENT & LOST FEATURES
- **PRESERVATION:** Keep all comments during refactoring to aid understanding. Ensure no features are lost when optimizing code.

---

### 7. UI & COMPONENTS
- **ACCESSIBILITY (BLOCKING):** Every interactive element (`button`, `input`, `select`, `range`) MUST have a `title` and `aria-label`. The linter treats missing labels as Severity 8 (Build Fail).
- **INLINE STYLES (WARNINGS):** Ignore "no-inline-styles" warnings (Severity 4) for dynamic components like `DraggableWindow`, `NodeGraph`, and `Gizmo`. These require runtime calculation of coordinates and cannot be moved to static CSS.
- **ICONS:** Verify icon names against the `lucide-react` library. Do not use non-existent names (e.g., use `Cuboid` instead of `Scene`).

---

### 8. BUILD & CONFIGURATION
- **STRICT MODE:** `tsconfig.json` must have `"strict": true` and `"forceConsistentCasingInFileNames": true` to pass validation.
- **TYPE DEFINITIONS:** Ensure `@types/react` and `@types/react-dom` are installed. Do NOT restrict `"types": ["node"]` in `tsconfig.json` as it breaks React type resolution.
- **CSS COMPATIBILITY:** Always include vendor prefixes for newer CSS features (e.g., `-webkit-backdrop-filter` alongside `backdrop-filter`) to support Safari/iOS.

---

### 9. ASSET VIEWPORTS & CODE INHERITANCE CONSISTENCY
- **INHERIT FROM `AssetViewport3D`:** All 3D asset editors (StaticMeshEditor, SkeletonEditor, MaterialEditor, etc.) MUST inherit from `editor/components/AssetViewport3D.tsx`. Never duplicate WebGL loop, HiDPI canvas handling, camera navigation math (orbit/pan/zoom), or ground grid buffers.
- **ALWAYS UPDATE DOCUMENTATION:** Whenever creating new components, changing architectural flows, or refactoring engine/editor layers, immediately update the relevant documentation in `/docs/` and summarize design decisions.
- **CONSISTENCY FLOW:** Keep tool shortcuts (`Q`, `W`, `E`, `R`, `G`, `F`), camera navigation (Alt+LMB/MMB/RMB), and UI styling consistent with the Scene View and existing asset editors.

---

### 10. RUNTIME SAFETY & DEPENDENCY RESOLUTION
- **NO IMPORT MAP CDN CONFLICTS:** Do not place `<script type="importmap">` tags in `index.html` pointing to external CDNs with mismatched major package versions (e.g. React 19 / rc-dock 4.0 alpha vs local React 18). In Vite applications, all dependency resolution is handled locally.
- **DEFENSIVE LOOKUP GUARDS:** Always guard Map lookups and ECS indices (`engineInstance?.ecs?.idToIndex?.get(...)`, `entityMap?.get?.(...)`, `perObjectModes?.get?.(...)`). Never assume instances or maps are fully populated during initial render or before asynchronous subscriptions fire.
- **SoA STORAGE FIELD CONVENTIONS:** In `ComponentStorage`, always reference transform arrays by their actual field names (`posX`, `posY`, `posZ`, `rotX`, `rotY`, `rotZ`, `scaleX`, `scaleY`, `scaleZ`), never assumed aliases like `positionX` or `rotationX`.
- **ASSET MUTATIONS VIA `assetManager.updateAsset`:** Maintain the generic `updateAsset(id: string, partial: Partial<Asset>)` contract on `AssetManagerService` with eventBus `ASSET_UPDATED` notification so all asset viewports and hierarchy panels can mutate asset fields consistently without missing method exceptions.

---

### 11. HIERARCHY TREE ELEMENTS & SHARED INLINE RENAMING API
- **INHERIT FROM `HierarchyTreeItem`:** Every UI element in hierarchical trees (Scene Hierarchy, Skeleton Bone Hierarchy, Asset trees) representing specific object types MUST use or inherit from `editor/components/HierarchyTreeItem.tsx`. Never re-implement bespoke indentation, tree expand/collapse chevrons, selection styling, or inline text inputs from scratch.
- **SHARED RENAMING HOOK (`useInlineRename`):** Use the shared `useInlineRename()` hook (`editor/hooks/useInlineRename.ts`) to manage inline renaming state across tree views and asset lists. This ensures consistent double-click rename, F2 shortcut, Enter-to-commit, Escape-to-cancel, and blur handling while preventing redundant state creation and optimizing memory.
- **ISOLATE KEYBOARD EVENTS ON EDIT:** Always call `e.stopPropagation()` on input keydown events during inline renaming so global viewport hotkeys (such as Q, W, E, R, F, Space, Delete) are not accidentally triggered while typing names.
- **ACCESSIBLE RENAMING INPUTS:** Ensure rename input fields always include descriptive `title="Rename item"` and `aria-label="Rename item"` attributes to comply with strict accessibility requirements.

---

### 12. SKELETON DISPLAY & INSPECTOR REUSABILITY
- **SELECTION SYSTEM CONTRACTS:** `SelectionSystem` maintains `selectedIndices: Set<number>` indexing the ECS store. To query whether an entity is selected, look up its ECS index with `ecs.idToIndex.get(entityId)` and check `selectedIndices.has(idx)`, or use `selectionSystem.isSelected(entityId)` / `selectionSystem.selectedEntities.has(entityId)`. Never call `.has()` on non-existent properties.
- **CONSISTENT SKELETON DRAWING PIPELINE (SPHERE-ONLY JOINTS):** Skeleton visualization (drawing joints, bones, and RGB coordinate axes) must remain mathematically and optically consistent between the global workspace (`SkeletonTool.ts`), asset-specific editors (`SkeletonEditor.tsx`), and animation playback (`AnimationSystem.ts`). All joints MUST be drawn as wireframe spheres (never diamonds or arbitrary dot sprites) across all contexts.
- **SCENE BONE TRANSFORM SYNCHRONIZATION:** Bone entities spawned into the scene graph (`engine.ts`) must initialize their local position, rotation, and scale by decomposing `bone.bindPose`. Furthermore, `ASSET_UPDATED` on a skeleton asset triggers `syncSkeletonEntities` so scene instances remain synchronized with skeleton editor additions, deletions, and transform updates.
- **MATCHING SCALING & COLOR PALETTES:** Skeletons in the Scene View (`SkeletonTool.ts`) and Skeleton Editor (`SkeletonEditor.tsx`) share identical joint radius formulas (`baseRadius * (jointRadius / 10) * rootScaleFactor`), bone octahedrons (soft off-white), and coordinate axes (only drawn when `drawAxes` is enabled, scaled with `(isSelected ? 0.22 : 0.16) * radiusScale * rootScaleFactor`).
- **CENTRALIZED GEOMETRY GENERATION (`DebugRenderer`):** Shared pure geometry generators (`generateWireSphereLines`, `generateBoneOctahedronLines`, `generateAxisLines`) and rendering methods (`drawWireSphere`, `drawAxis`, `drawBoneOctahedron`) are centralized in `engine/renderers/DebugRenderer.ts`. Never write duplicate private line-generation algorithms in tools or asset viewports.
- **USE REUSABLE `SkeletonDisplayOptions`:** Always use `editor/components/inspector/SkeletonDisplayOptions.tsx` to render skeleton visualization controls (`enabled`, `drawJoints`, `drawBones`, `drawAxes`, `jointRadius`, `rootScale`). Never hardcode duplicate checkbox and slider sets across `InspectorPanel`, `ToolOptionsPanel`, or asset viewports.
- **DECOUPLED STATE BINDING:** `SkeletonDisplayOptions` accepts decoupled `options: SkeletonVizSettings` and `onChange: (opts: SkeletonVizSettings) => void` props, allowing it to bind to global `EditorContext` (for global tools and entity inspection) or component-local state with equal fidelity.
- **INSPECTOR AS SINGLE POINT OF CONTROL:** When editing specific assets in dedicated viewports (such as `SkeletonEditor`), provide a dedicated right-side Inspector panel containing `JointInspector` (when a joint is selected) and `SkeletonAssetInspector` (when inspecting the skeleton asset), while embedding `SkeletonDisplayOptions` for unified visualization management.
- **ACCESSIBLE FORM CONTROLS:** All checkboxes, range sliders, numeric inputs, and buttons in skeleton and inspector components must declare descriptive `title` and `aria-label` attributes to maintain accessibility standards.

### 13. UNIFIED JOINT & BONE SELECTION AND HIERARCHY TRIGGERING
- **UNIFIED JOINT & BONE OBJECT BEHAVIOR:** A bone connecting parent joint $J_1$ to child joint $J_2$ is conceptually part of the parent joint $J_1$. Clicking or raycasting the bone segment in 3D (both in Scene View via `SelectionSystem.ts` ray-segment intersection and in Skeleton Editor via 2D segment projection) selects $J_1$.
- **COHESIVE HIGHLIGHTING:** When joint $J_1$ is selected, both $J_1$'s joint sphere AND its outgoing bone octahedron(s) are highlighted with the identical golden amber accent (`#fbbf24` / `rgba(0.98, 0.65, 0.12, 1.0)`). They appear and interact as one continuous entity.
- **ZERO-LATENCY HIERARCHY SELECTION TRIGGER:** In `HierarchyTreeItem.tsx` and `HierarchyPanel.tsx`, selection is bound to `onPointerDown` (debounced against subsequent `onClick`) and `onDragStart`. Because native HTML5 `draggable={true}` can absorb clicks upon cursor movement, binding `onPointerDown` guarantees 100% trigger reliability without missing clicks or drag activations.
- **ISOLATE SELECTION EVENT PROPAGATION:** In `HierarchyTreeItem.tsx`, `handleSelectTrigger` must always invoke `e.stopPropagation()`. Furthermore, all hierarchy containers with background deselect handlers (such as `SkeletonHierarchy.tsx`) must strictly check `if (e.target === e.currentTarget)` before deselecting; otherwise, releasing a mouse press (`click`) over a child item will bubble to the container and immediately deselect the clicked item.
- **SYNCHRONOUS SELECTION REACTION:** In `SkeletonEditor.tsx` and `engine.ts`, `handleSelectBone` and `engine.setSelected` immediately update refs, sync transforms (`engine.syncTransforms(false)`), and call `engine.notifyUI()` synchronously so Gizmo, Inspector, and Viewport respond on the exact frame selection occurs without reactive lag.

---

### 14. GIZMO INTERACTION & TRANSFORM API IN ASSET VIEWPORTS
- **PASS LIVE INSTANCES TO `AssetViewport3D` VIA STATE:** `AssetViewport3D` requires `engine` and `gizmoSystem` props to bind renderer facades and run the gizmo render/interaction loops. Never pass stale or uninitialized `ref.current` values that do not trigger re-renders upon creation in `useEffect`. Store engine and gizmo system in local `useState` (`[previewEngine, setPreviewEngine]`, `[gizmoSystem, setGizmoSystem]`) so `AssetViewport3D` safely receives live instances on mount.
- **ATTACH GIZMO RENDERER FACADE DYNAMICALLY:** In `AssetViewport3D`, track `gizmoRendererRef`. When `engine` updates via prop changes, immediately wire `engine.setRenderer({ renderGizmos: (...) })`. Never rely solely on the initial WebGL mount effect, which executes before child asset editors create their engine instances.
- **KEEP UI TRANSFORMS LIVE DURING GIZMO DRAG:** In asset editors (`SkeletonEditor`, `StaticMeshEditor`), ensure `onNotifyUI` triggers a reactive revision tick (`setTransformRevision(r => r + 1)`). Pass this revision to inspectors (`JointInspector`) so numeric input fields (X, Y, Z coordinates, rotation, scale) reflect real-time gizmo translation without waiting for mouse release or manual reload.
- **ALWAYS MARK SCENE GRAPH DIRTY ON TRANSFORM APPLIES:** When modifying ECS component store coordinates (`store.setPosition`, `store.setRotation`, `store.setScale`), always invoke `sceneGraph.setDirty(entityId)` followed by `sceneGraph.update()`. In `AssetViewportEngine`, use `sceneGraph.setDirty` (never nonexistent `markDirty`) and pass 4 numeric arguments `(idx, x, y, z)` (never an object `{x, y, z}`).
- **UNIFIED ENGINE API COMMANDS (`EngineAPI`):** `EngineAPI.commands.transform` (`setPosition`, `setRotation`, `setScale`, `move`, `setWorldPosition`) and `EngineAPI.commands.gizmo` (`setTool`) provide a stable, decoupled interface for moving and transforming objects across viewports and UI panels without direct coupling to engine singletons.

---

### 15. ECS TRANSFORM PROXY DIRTY FLAG & MULTI-ENGINE INSPECTOR CONTROL
- **SOA TRANSFORM DIRTY FLAG PROPAGATION:** Whenever modifying entity transform coordinates through proxy getters/setters (`transformProxy.position`, `rotation`, `scale`) or individual axis coordinates (`.x`, `.y`, `.z`), always set `store.transformDirty[index] = 1` in addition to calling `sceneGraph.setDirty(id)`. Without setting `transformDirty`, `ComponentStorage.updateWorldMatrix` skips matrix recalculation, causing 3D objects to appear locked/frozen during numeric inspector edits or gizmo updates.
- **SYNC TRANSFORMS ON TRANSFORM COMPONENT UPDATE:** In inspector panels (`InspectorPanel.tsx`), when updating the `TRANSFORM` component, invoke `engineInstance.syncTransforms(true)` rather than just `notifyUI()`. This ensures the scene graph matrix recalculates before the UI re-renders.
- **REUSABLE INPUT CONTROLS WITH LOCAL STRING DRAFTING:** Numeric inputs like `DraggableNumber` and `Vector3Input` (`editor/components/ui/InputControls.tsx`) must manage local string drafts on focus to permit typing minus signs, decimal points, and multi-digit values without race conditions against high-frequency engine notify events. Commit changes on blur and pointer release.

---

### 16. ZERO-LATENCY DEPTH-AWARE JOINT & BONE DETECTION
- **SYNCHRONOUS HIT-TESTING:** Never defer hover or click detection exclusively to the `requestAnimationFrame` render loop (`handleRender`). When the mouse moves (`onMouseMove`), run `findBoneAtScreen` immediately to update hover states and tooltips synchronously for 0ms lag. When the mouse clicks (`onMouseDown`), execute `findBoneAtScreen` synchronously at the exact click coordinates instead of reading a stale ref from the previous frame.
- **JOINT SPHERE HIT PRIORITY OVER BONE SEGMENTS:** Joint spheres are primary interactive handles. If the cursor is within the joint hit threshold (22px), a joint MUST be selected. Bone segment line tests must NEVER override or replace a direct joint hit.
- **3D DEPTH / OCCLUSION SORTING:** In 3D viewports, multiple joints or bones can project to nearby screen coordinates (e.g., overlapping limbs or joints viewed in profile). Always sort candidates by camera view depth (`pw`), prioritizing elements visually closest to the camera (smaller `pw`). Use screen-space proximity only as a tie-breaker when depth differences are negligible (<= 0.05).
- **GIZMO INTERACTION SEPARATION IN SELECT MODE:** In asset viewports like `SkeletonEditor`, ensure `gizmoSystem.renderInSelectTool = false`. When the `SELECT` tool (Q) is active, gizmos must neither render nor intercept mouse events. When transform tools (`MOVE`, `ROTATE`, `SCALE`) are active, clicking another joint outside of active axis/plane handles must immediately transfer selection to that joint.
- **CLEAN AXES STATE ON EARLY RETURNS:** In `GizmoSystem.update`, always reset `this.hoverAxis = null` and `this.activeAxis = null` on early returns (e.g., when selection is empty or entity is invalid) to prevent ghost active axes from blocking viewport clicks.

### 17. STATIC CODE HEALTH, ANIMATION SAMPLING & ASSET EVENT CONTRACTS
- **RUN THE REPOSITORY AUDIT:** Use `npm run audit` before typechecking/building. It validates strict TS configuration, local imports, `drafts/` exclusion, import-map safety, and `AssetViewport3D` inheritance without requiring installed npm packages.
- **CANONICAL GRAPH CONNECTION FIELDS:** New graph code uses `fromNode`, `fromPin`, `toNode`, and `toPin`. Treat `source` / `target` only as optional legacy compatibility fields.
- **CENTRALIZE ANIMATION TRACK SAMPLING:** `AnimationEvaluator` is the single source of truth for keyframe interval selection and interpolation. Do not duplicate interpolation loops in `AnimationSystem` or editor preview code; duplicated logic previously selected the wrong interval and mishandled the final/single-keyframe cases.
- **REQUIRE RUNTIME TRACK DATA:** Runtime `AnimationTrack` data requires `name`, `type`, `times`, and `values`. Keep editor-only metadata optional rather than weakening the runtime sampling contract.
- **MATCH ASSET EVENTS TO CREATED TYPES:** `ASSET_CREATED` payload type must exactly match the asset created. A skeletal mesh emits `SKELETAL_MESH`; never emit `SKELETON` for a mesh asset.
- **GUARD REVERSE MESH LOOKUPS:** `AssetManager.getMeshUUID(intId)` may return `undefined`. Asset viewport vertex-drag code must return early when reverse lookup fails.
- **ACCESSIBILITY AUDIT WARNINGS ARE RELEASE WORK:** `npm run audit` reports controls missing either `title` or `aria-label`. Do not suppress these warnings; resolve them before a release because Section 7 treats the convention as blocking.

### 18. REUSABLE VIEWPORT TEMPLATE & CAMERA MATH
- **USE `ViewportTemplate` FOR VIEWPORT SHELLS:** Main renderer-backed viewport hosts must compose their canvas/chrome through `editor/components/viewport/ViewportTemplate.tsx` instead of duplicating absolute toolbar/HUD layout and canvas wrapper styling.
- **ASSET EDITORS STILL USE `AssetViewport3D`:** `ViewportTemplate` is a lower-level shell, not a replacement for the asset viewport contract. Static mesh, skeleton, material, animation, and similar asset editors must inherit from `AssetViewport3D`.
- **KEEP RENDER LIFECYCLES OUT OF THE TEMPLATE:** Do not initialize WebGL, own engine singletons, or start render loops inside `ViewportTemplate`. Renderer lifecycle remains in `SceneView`, `AssetViewport3D`, or another explicit host.
- **REUSE VIEWPORT CHROME PRIMITIVES:** Prefer `ViewportToolbarGroup`, `ViewportIconButton`, and `ViewportHud` over copying the same toolbar/HUD Tailwind classes. `ViewportIconButton` requires a label and supplies both `title` and `aria-label`.
- **CENTRALIZE CAMERA NAVIGATION MATH:** Use `editor/viewports/viewportCamera.ts` for eye calculation, orbit, pan, drag zoom, and wheel zoom. Configure limits/sensitivity per host rather than copying vector math.

### 19. FULL ASSET EDITOR TEMPLATE & ASSET-TYPE ACTION FILTERING
- **FULL 3D ASSET EDITORS USE `AssetEditorTemplate`:** Static mesh and skeleton workspaces must not hand-build separate left/center/right shells. Use `AssetEditorTemplate` for Hierarchy + Viewport + Inspector and `AssetViewport3D` for the center renderer.
- **CAPABILITY REGISTRY IS THE SOURCE OF TRUTH:** Add/edit valid commands in `editor/components/asset-editor/assetViewportCapabilities.ts`. Toolbar visibility, keyboard shortcuts, pie/context actions, and hierarchy mode triggers must check the same action id.
- **PREFER TOOLBAR ACTION DESCRIPTORS:** Normal asset toolbar controls use `AssetViewportToolbarAction` descriptors and are filtered inside `AssetViewport3D`. Reserve raw `toolbarExtra` for exceptional composition that cannot be expressed as an action.
- **SKELETAL MESH HAS TWO WORKSPACES:** `SKELETAL_MESH` opens `SkeletalMeshEditor`, with Geometry reusing `StaticMeshEditor` and Skeleton reusing `SkeletonEditor`. Never duplicate either renderer to create a separate skeletal-mesh-only implementation.
- **KEEP PASSIVE STATUS OUT OF ACTIVE TOOL SPACE:** Asset stats/selection badges belong in the viewport HUD. Keep top chrome primarily for actions to avoid collisions at smaller window sizes.
- **SIDE PANELS MUST BE COLLAPSIBLE:** Hierarchy and Inspector default to visible but are controlled by the shared asset editor header so narrow windows remain usable.

### 20. RUNTIME SELECTION API & LOCAL TAILWIND BUILD
- **USE THE REAL SELECTION API:** `SelectionSystem` exposes `selectedIndices`, the derived `selectedEntities` set, and `isSelected(id)`. Never read `selectionSystem.selectedEntityIds`; that property does not exist and will make calls such as `Array.from(...)` crash at runtime.
- **KEEP TAILWIND IN THE VITE BUILD:** Tailwind must be compiled locally through `tailwind.config.cjs` + `postcss.config.cjs` and the `@tailwind` directives in `index.css`. Never add `cdn.tailwindcss.com` back to `index.html`; the CDN runtime is not for production builds.
- **AUDIT THESE CONTRACTS WITHOUT DEPENDENCIES:** `npm run audit` must reject both stale `selectionSystem.selectedEntityIds` usage and Tailwind CDN usage so runtime/config regressions are caught before launching Vite.

### 21. BONE VISUAL TYPES & TYPESCRIPT 6 PATH MAPPING
- **BONE COLORS USE `Vector3`:** `BoneData.visual.color` is the canonical `{ x, y, z }` shape. New joints must not write numeric arrays such as `[0, 1, 0]`; type new bone literals as `BoneData` so mismatches fail at the creation site.
- **DO NOT RESTORE `baseUrl`:** TypeScript 6 deprecates `compilerOptions.baseUrl`. Keep `paths` entries rooted explicitly (for this repo, `"@/*": ["./*"]`) and let Vite own the matching runtime alias.
- **AUDIT THE TS6 CONFIG CONTRACT:** `npm run audit` must reject a reintroduced `baseUrl` so editor/compiler upgrades do not revive the deprecation.

### 22. STRICT EDITOR API / TOOL OPTION CONTRACTS
- **RENAME ECS ENTITIES THROUGH SUPPORTED STORAGE/PROXIES:** `SoAEntitySystem` has no `setName(id, name)` method. Resolve the entity index and update `ecs.store.names[index]`, or set the name through a valid entity proxy. Never invent convenience methods at call sites.
- **REPARENT WITH `SceneGraph.attach`:** `SceneGraph` has no `detach`. `sceneGraph.attach(childId, parentId)` already removes the old parent; pass `null` as the parent to make the child a root.
- **GUARD OPTIONAL MODULE METADATA:** `EngineModule.name` and `EngineModule.icon` are optional. Inspector UI must fall back to `module.id` and a valid default icon rather than passing `undefined` to required display props.
- **DEFAULT OPTIONAL UI CONFIG VALUES AT USE SITES:** Persisted `UIConfiguration` fields such as `vertexSize` may be missing. Controls that require concrete values must apply the editor default (`vertexSize ?? 1.0`).
- **GUARD ASSET PREVIEW ENTITY IDS:** `AssetViewportEngine.entityId` is `string | null` until preview setup completes. Rendering and component-picking code must return/fallback before passing it into APIs that require a string.
- **ONLY EXPOSE IMPLEMENTED TRANSFORM SPACES:** The current `TransformSpace` contract is `World | Local`. Do not show Gimbal, Parent, VirtualPivot, Object, Normal, or Average options until engine behavior exists for them; UI-only casts create invalid runtime state.
- **KEEP LUCIDE ICON NAMES TYPE-SAFE:** `Icon.name` is `keyof lucide-react`. Use real exports (for example `Wrench`) instead of invented names such as `Tool`; do not silence this with broad casts.
- **AUDIT STALE API NAMES:** The dependency-free audit must reject `.ecs.setName(`, `.sceneGraph.detach(`, invalid `name="Tool"`, and unsupported transform-space option values.
- **NARROW OPTIONAL DISCRIMINATED UNIONS EXPLICITLY:** When a value can be `null | undefined | Union`, guard the value and its discriminator in one explicit `if` before reading variant-only fields. Do not rely on a mixed optional-chain/`&&` ternary such as `value?.id === x && value.mode === 'FACE' ? value.faceId : null`; strict TypeScript may not carry that narrowing to the variant member access.

### 23. VIEWPORT MARQUEE SELECTION & BVH PICKING SPACE
- **FINALIZE MARQUEE ON GLOBAL MOUSE-UP:** Rectangle selection must commit from the window/global mouse-up path, not only from the viewport element. Releasing a drag outside an edge/corner otherwise loses the local mouse-up and leaves selection stuck or apparently disabled.
- **CLAMP MARQUEE COORDINATES TO LIVE CSS BOUNDS:** Track rectangle coordinates in viewport CSS pixels and clamp global pointer positions to `getBoundingClientRect()` before drawing/finalizing. Pass the live rect width/height into `SelectionSystem.selectEntitiesInRect`; never mix CSS picking coordinates with HiDPI canvas pixel dimensions.
- **ISOLATE VIEWPORT CHROME INPUT:** Shared toolbar overlays must stop `mousedown` propagation so toolbar presses cannot also trigger canvas selection underneath. Global marquee finalization still allows drags that started on the canvas to end over toolbar chrome.
- **RECTANGLE SELECTION DOES NOT USE THE RAYCAST BVH:** Marquee selection is screen-space. Use projected AABB only as broad phase, then refine mesh candidates against projected triangles. Debug the raycast BVH only for click/component picking; it is not the source of marquee air-gap false positives.
- **NEVER ACCEPT PROJECTED MESH AABB AS THE FINAL MARQUEE HIT:** Perspective-projected AABB corners can lie outside a curved/concave silhouette (a sphere is the canonical case), producing selection through visible air gaps. After broad-phase overlap, require projected mesh-triangle/rectangle overlap; use AABB only as a fallback when triangle data is unavailable.
- **NEVER COMPARE LOCAL AABB `t` WITH WORLD HIT DISTANCE:** Mesh click rays are transformed and normalized into local space before AABB/BVH traversal. Compare candidate distances only after transforming the precise/fallback hit back into world space.
- **KEEP MESHES SELECTABLE WITHOUT TOPOLOGY:** If a mesh has a geometry AABB but no logical faces/BVH, object-level click picking falls back to the AABB rather than returning no hit.
- **USE PARALLEL-SAFE AABB SLABS:** `RayUtils.intersectAABB` must explicitly handle near-zero ray directions. Direct slab division can yield `0/0 -> NaN` for axis-aligned rays on box boundaries and cause intermittent BVH misses. When the ray origin is inside an AABB, return entry distance `0` (not the exit distance) so BVH nearest-hit pruning remains valid.
- **KEEP COMPONENT PICKING IN ONE COORDINATE SPACE:** `pickMeshComponent` returns a world-space hit. Vertex hover should compare in screen space (pixel threshold) or transform the vertex to world first; never compare the world hit directly to local vertex coordinates. Topology/BVH sphere queries use local vertices, so transform brush centers back to local space and use absolute guarded entity scale when deriving a local radius.
Selection gesture: never commit object/bone raycast selection on left mousedown; cache the hit and only commit on mouseup if movement stayed below the marquee threshold. Otherwise projected geometry becomes a dead zone for rectangle selection.

### 24. STABLE PARENT-LOCAL BONE VISUAL GEOMETRY
- **DO NOT SCALE BONE WIDTH FROM PARENT-CHILD DISTANCE:** Bone length follows the live child, but the four-point waist/cross-section must derive from the parent joint's normal structural radius. Never restore `len * ...` width calculations.
- **ANCHOR BONE ROLL TO THE PARENT LOCAL FRAME:** Build bone visual orientation from normalized parent joint axes plus a stable local/rest direction. Do not choose arbitrary world-up vectors from the live child direction; that produces roll flips/twisting.
- **DO NOT USE LIVE-MUTATING `bindPose` AS THE EDITOR REST FRAME:** `SkeletonEditor` writes `bindPose` during gizmo movement. Snapshot local visual rest directions when the preview engine/rebuild starts, then transform those snapshots through the current parent axes during the drag.
- **SELECTION MUST NOT CHANGE BONE THICKNESS:** Selected/hovered joint spheres may grow for feedback, but attached bone width must use `getSkeletonJointRadius(..., 'normal')`.
- **REUSE SHARED DEBUG-RENDERER HELPERS:** SkeletonEditor, SkeletonTool, and AnimationSystem must all use `generateBoneOctahedronLines` / `drawBoneOctahedron` with parent radius, parent axes, and stable rest direction. Do not create a second bone shape algorithm.
- **ONLY SHORT-BONE OFFSET MAY CLAMP:** Extremely short bones may clamp the waist distance so the base does not pass the child. The cross-section radius remains fixed from the parent joint radius.
- **BONE SURFACE-TO-SURFACE VISUALS:** A skeleton bone must not render from the parent joint center. Use the parent center only as the pivot; place the four-point base outside the parent sphere along the live parent->child direction, clip the tapered tip at the child sphere surface, keep width based only on the parent's normal joint radius, and transport the parent-local rest frame to the live direction with a shortest-arc rotation to avoid arbitrary axial twist. Do not pin the base to the rest direction and do not use world-up to rebuild roll each frame.

React / skeleton editor update-loop guard:
- Do not emit ASSET_UPDATED for every gizmo mouse-move in SkeletonEditor. Live bind-pose edits belong to the private skeleton edit draft; the global asset update occurs only on explicit Confirm, never on drag mouse-up.
- DraggableNumber must derive its unfocused display value from props; do not use a passive effect that mirrors value into local state on every transform update.

### 25. SKELETON EDIT TRANSACTIONS / CONFIRMED POSE
- **SAVED POSE IS READ-ONLY:** Outside Skeleton Edit mode, the preview must be rebuilt from the last confirmed AssetManager skeleton. Allow selection/camera/display controls, but never permit transform, rename, reparent, add, or delete writes.
- **EDIT A PRIVATE DRAFT:** Entering Edit Skeleton deep-clones `BoneData[]` (including bind/inverse-bind matrices and visual data). Inspector, hierarchy, and gizmo edits target that draft; do not mutate the AssetManager skeleton by reference.
- **CONFIRM IS THE ONLY PERSIST BOUNDARY:** `AssetManager.updateAsset` for a SkeletonEditor edit transaction belongs in explicit Confirm. Gizmo mouse-up only ends the gesture; it does not save.
- **CANCEL MEANS EXACT RESTORE:** Cancel discards the private draft and rebuilds from the confirmed pose. An unconfirmed editor unmount/workspace switch must likewise leave the saved asset unchanged.
- **RESET STAYS IN EDIT MODE:** Reset replaces the draft from the confirmed pose but keeps Edit mode active so a user can restart the edit without leaving the workflow.
- **LOCK ALL MUTATION SURFACES:** In Saved Pose mode filter AssetViewport3D to Select only, disconnect the gizmo system, disable JointInspector mutation controls, and disable SkeletonHierarchy rename/context structural edits. Do not rely on UI hiding alone; mutation handlers must also guard `editable/isEditMode`.
- **KEEP TOOL FILTERING REUSABLE:** Use `AssetViewport3D.allowedTools` so host-specific modes can restrict both toolbar and keyboard tool activation through one contract.

### 26. SHARED MESH / POLYGON EDGE RENDERING
- **ONE EDGE ID:** Use `meshEdgeKey(a, b)` from `engine/MeshEdgeGeometry.ts` everywhere. Do not recreate edge ids with local `sort().join('-')` expressions.
- **TOPOLOGY FACES ARE AUTHORITATIVE:** Wireframe/poly-edge rendering must use logical `topology.faces` when available so triangulation diagonals are not shown as authored polygon edges. Triangle indices are fallback only.
- **DEDUPLICATE SHARED EDGES:** Use `forEachUniqueMeshEdge` / `buildMeshEdgeIndices`; never draw every face boundary directly because adjacent faces will draw the same edge twice and change brightness.
- **REUSE `MeshEdgeOverlay` IN ASSET VIEWPORTS:** Static Mesh, Skeleton-associated mesh previews, and future mesh asset editors must not create bespoke edge VAO/IBO code.
- **WEBGL2 ELEMENT BUFFER STATE:** `ELEMENT_ARRAY_BUFFER` is VAO state. Bind the edge overlay VAO before replacing/updating its IBO or the host mesh VAO can be corrupted.
- **COMPONENT TOPOLOGY CAGE:** Vertex/Edge/Face edit modes keep a dim edge cage visible independent of the explicit object Wireframe toggle. Edge/Face selection is a second highlighted edge pass.
- **HIDDEN-LINE WIREFRAME:** Wireframe-only previews must populate mesh depth first and use polygon offset before drawing the shared edge overlay; otherwise back-side edges show through or front edges z-fight.
- **DO NOT USE `gl.lineWidth` FOR PORTABLE THICK EDGES:** WebGL line width is commonly clamped to 1px. A future thick-edge feature should use screen-space expanded line geometry.
- **COMPONENT OVERLAYS MUST NOT DEPTH-BLOCK EACH OTHER:** Mesh edge/vertex overlays should depth-test against the shaded mesh with `LEQUAL`, but keep `depthMask(false)` while drawing. A dim topology cage or base point pass must never write the exact surface depth and hide the selected/highlight pass rendered immediately after it.
- **VERTEX MODE MUST USE THE SHARED POINT OVERLAY:** `StaticMeshEditor` Vertex mode renders base, selected, and hovered vertices through `MeshVertexOverlay` using the host position VBO. Do not add per-editor point buffers/VAOs or omit the point pass while keeping vertex picking enabled.

[Mesh vertex marker sizing]
- Do not hardcode different gl_PointSize values in Scene and asset-edit viewports.
- Treat uiConfig.vertexSize as CSS-pixel visual scale, then multiply by the active viewport framebuffer/CSS pixel ratio.
- Reuse engine/MeshComponentVisualStyle.ts for base/selected/hovered vertex sizes.
- Vertex markers are screen-space editor UI: camera zoom must not change their pixel size independently.
- Developer flow reference: see `docs/MESH_COMPONENT_RENDERING_FLOW.md` before changing mesh component visualization, render ordering, depth behavior, or point-size/DPR logic.

### 27. SHARED VIEWPORT MESH SURFACE / COLOR MANAGEMENT
- **ONE STANDARD SURFACE IMPLEMENTATION:** Scene generated Standard materials, Scene fallback mesh rendering, and asset-preview Lit shading must reuse `engine/renderers/MeshSurfaceContract.ts -> STANDARD_SURFACE_GLSL`. Never copy GGX/Fresnel/fake-IBL equations into `AssetViewport3D`, `StaticMeshEditor`, or another preview.
- **KEEP RENDER MODE IDS SHARED:** `MESH_SURFACE_RENDER_MODE` is the source of truth for `LIT=0`, `NORMALS=1`, `UNLIT=2`. Do not restore the old asset-only `Flat=1 / Normals=2` mapping.

Direct asset-preview mesh/line shaders must perform that same display transfer themselves. Never apply gamma twice and never omit it from a direct preview.

- **SURFACE != ENVIRONMENT:** A shared BRDF does not imply identical Scene/asset inputs. Scene can use a custom material, entity tint, actual scene light, texture graph, skinning, and effects; mesh assets currently preview the default Standard material with neutral preview light. Add explicit preview-material/environment inputs if exact parity is required—never reintroduce a bespoke asset shader.
- **DEVELOPER REFERENCE:** Read `docs/SHARED_VIEWPORT_MESH_SHADING.md` before changing mesh Lit/Normals/Unlit shading, gamma/color output, viewport background, or canvas antialias policy.

### 31. VIEWPORT PROFILE / CAMERA SOURCE SEPARATION
- **VIEWPORT != CAMERA:** Camera owns lens; live Scene Camera pose belongs to Transform. Grid, helpers, gizmos, and orbit/pan/zoom/focus availability belong to `VIEWPORT_PROFILE` / viewport host.

- **LIVE CAMERA NAVIGATION COMMITS TRANSFORM:** Scene View orbit/pan/perspective zoom while bound to a Camera must flow through shared `viewportCamera.ts` math. Keep the live gesture in viewport-local `CameraState`, then commit the final pose through `writeSceneCameraViewportState(...)` once at mouse-up / wheel-idle so the Camera entity moves/rotates without dirtying the SceneGraph per pointer sample.

### SCENE CAMERA VIEW-THROUGH STABILITY
- **ONE ACTIVE DRIVER PER GESTURE:** While a Scene viewport is orbiting/panning/zooming a bound Camera, do not resync CameraState from Transform notifications. The viewport owns the gesture; Transform is the committed scene state.
- **NO FULL SCENEGRAPH UPDATE PER POINTER SAMPLE:** `writeSceneCameraViewportState` may dirty the Camera branch but must not call whole-scene `sceneGraph.update()` on every mousemove. Resolve only required parent matrices and let the render/update loop process dirtiness.
- **TRANSPORT ROLL, DO NOT FREEZE WORLD UP:** Orbit state must represent Camera roll as a scalar around the live forward direction. Keeping the original world-space `up` vector while forward changes causes flips/corkscrew rotation. Use `getCameraUp()` / `cameraStateFromWorldPose()`.

Mouse-up / wheel-idle flushes the final React pose, writes Transform once, calls `notifyUI()` while the self-resync guard is still active, then releases ownership.

### 32. VIEWPORT FOCUS / CONTEXT SEPARATION
- **FOCUS IS EXPLICIT NAVIGATION:** Selection changes must never move or reframe a viewport automatically. Only an explicit Focus/Reset/navigation command may change camera state.

- **DO NOT TEACH `AssetViewport3D` DOMAIN TYPES:** Mesh vertices, edges, faces, bones, etc. belong in focus providers/resolvers. `AssetViewport3D` accepts `ViewportFocusProvider` and stays domain-neutral.
- **REUSE COMPONENT SELECTION CONVERSION:** Mesh component focus must reuse `SelectionSystem.getSelectionAsVertices()` so vertex/edge/face modes share one topology conversion contract.
- **BOUND CAMERA COMMITS:** Scene View Through Camera focus must commit through `writeSceneCameraViewportState(...)`; never write Camera Transform fields directly from focus code.
- **API-FIRST:** External UI commands should call `AssetViewport3DHandle.focus()` / `focusTarget(...)` (or future editor API wrappers) instead of simulating keyboard input or copying navigation math.

- **STATIC MESH DEFORMATION MUST BE BASELINE-REPRODUCIBLE:** Fixed and Live Falloff transforms must reconstruct preview geometry from the operation-start vertex snapshot plus current total gizmo delta. Never compound Live deformation from the previous preview. ### 28. STATIC MESH ASSET EDIT SESSION / LIVE SCENE SYNC
- **SHARE COMMANDS, NOT TRANSIENT VIEWPORT STATE:** Static Mesh Editor may reuse Scene command IDs and mesh-editing implementations, but it owns its own tool, component mode, soft-selection settings, and heatmap visibility. Never bind those asset-editor states directly to Scene `EditorContext`; otherwise Scene shows component cages/heatmaps and its gizmo reacts while another viewport is active.
- **ONE GIZMO INPUT OWNER PER ASSET VIEWPORT:** `AssetViewport3D` owns `GizmoSystem.update()` for mouse down/move/up. Host editors may do picking/hover in forwarded callbacks, but must never call `GizmoSystem.update()` again. Double-driving the lifecycle can clear `activeAxis`, end a drag twice, or make the gizmo disappear until the editor is rebuilt.
- **LIVE GEOMETRY PREVIEW != ASSET COMMIT:** During direct Static Mesh deformation, emit `MESH_GEOMETRY_PREVIEW_UPDATED` to refresh Scene position/normal GPU buffers. Emit the normal `ASSET_UPDATED` event once when the gesture/finalization boundary is reached. Do not run the full asset pipeline on every mouse move.
- **CPU CAGE AND GPU SOLID MUST INVALIDATE TOGETHER:** Scene component overlays read asset CPU vertices directly while solid meshes use GPU VBOs. If asset geometry mutates without a GPU preview invalidation, the viewport shows a new cage over an old solid mesh.
- **REUSE GPU BUFFERS FOR LIVE EDITING:** `MeshRenderSystem.registerMesh`/preview update paths must reuse VBO/NBO/IBO objects where possible. Never allocate fresh geometry buffers on each drag event; that leaks GPU resources and destabilizes VAO state.
- **ASSET HEATMAP OBSERVES SESSION WEIGHTS:** Static Mesh Editor heatmap uses the same `AssetViewportEngine.softSelectionWeights` produced by deformation. Upload it as the shared soft-weight vertex attribute; do not recompute a second heatmap weight set in rendering code.

### 16. VIEWPORT HOTKEY CONTEXT
- **ACTIVE VIEWPORT OWNS GLOBAL SHORTCUTS:** Scene and asset editors can be mounted simultaneously. Any window-level viewport shortcut must be gated through `ViewportInputRouter`; never let every mounted viewport react to the same `keydown`.
- **CLAIM ON POINTER CONTEXT:** Viewports claim input ownership on pointer enter/down. Scene is the fallback only when no asset viewport is active.
- **NO GLOBAL EDITOR STATE IN BRUSH HOOKS:** Reusable gestures such as `B` radius adjustment must receive a host API adapter (`configureSoftSelection`) and local state. Do not read/write Scene `EditorContext` from a generic viewport interaction hook.
- **GESTURES BELONG TO THEIR START VIEWPORT:** B + LMB may start only when the mouse-down target belongs to the currently active viewport. Continue move/up globally only after that gesture has started.
- **ONE MESH CONNECTIVITY CONTRACT:** Surface soft selection, neighbor queries, shortest surface paths, and modeling adjacency must use `engine/mesh-editing/MeshConnectivity.ts`. Never rebuild a separate adjacency graph from triangle indices inside a tool; triangle diagonals are not authored polygon edges.
- **CONNECTIVITY IS TOPOLOGY, NOT PROXIMITY:** Use `LogicalMesh.faces` plus persistent **explicit** `siblings` for seam/hard-edge welding. Never create connectivity because vertices happen to be near/coincident. Direct Static Mesh deformation may only **split an existing sibling weld** at transaction finalization when its members were edited apart; that repair must rebuild propagated topology maps and invalidate connectivity. Explicit topology-changing operations must also call `MeshConnectivityAPI.invalidate(topology)` after rebuilding faces/siblings.
- **LOOP != SHORTEST PATH:** Keep quad/strip loop traversal in `MeshTopologyUtils`; use `MeshConnectivityAPI.shortestVertexPath` for geometric shortest paths. Do not substitute one algorithm for the other.

### 17. SOFT-INFLUENCE METRIC / CONNECTIVITY SEPARATION
- **DISTANCE != CONNECTIVITY:** Keep `VOLUME | SURFACE | HYBRID` as the distance/weight metric and `NONE | SAME_ISLAND | FLOOD_WITHIN_RADIUS` as an orthogonal topology mask. Do not create one special-case solver per combination.
- **TOPOLOGY NEIGHBORS REMAIN AUTHORED EDGES:** `MeshConnectivityAPI.neighbors()` is for real logical polygon edges. Never add face diagonals/virtual face centers to topology neighbor queries just to make a brush look rounder.
- **FACE-CENTER LINKS ARE METRIC ONLY:** Soft-selection Surface may use `faceAwareSurfaceDistances()` to cross polygon interiors. Loop/Ring/Extrude/valence/boundary tools must never observe those virtual links.
- **CONNECTED VOLUME IS A RADIUS-LIMITED FLOOD:** `FLOOD_WITHIN_RADIUS` walks cached logical neighbors and stops a branch when the next vertex is outside the Euclidean radius. It is intentionally cheaper and behaviorally different from geodesic Surface distance.
- **HYBRID BLENDS WEIGHTS, THEN MASKS:** Blend final Volume/Surface weights with `surfaceBlend`, then apply connectivity. This keeps endpoints exact (`0 = Volume`, `1 = Surface`) and makes heatmap/deformation share one weight buffer.
- **ONE CONFIGURATION API:** Scene UI, Static Mesh dock, brush hotkeys, scripts, and future agents must route these settings through `meshEditing.configureSoftSelection(...)`. Do not add renderer-only copies of surfaceBlend/connectivity state.
- **COMPONENT EMPTY-CLICK CLEARS THROUGH THE COMPONENT API, NEVER OBJECT PICKING:** In Static Mesh Vertex/Edge/Face mode, a plain LMB miss means `REPLACE` the active component selection with an empty set via `setMeshComponents(...)`; this intentionally clears the heatmap and gizmo. Do not fall through to `SelectionSystem.setSelected()`/object picking. `Shift+LMB` on empty space and RMB/pie-menu opening preserve the current component selection.
- **GIZMO DRAG OWNS ITS TARGET UNTIL MOUSE-UP:** Capture drag entity + component/object mode at gizmo mouse-down. Do not re-resolve selection on every pointer sample or clear `activeAxis` because of transient UI/selection notifications.
- **NO REACT INVALIDATION PER GIZMO SAMPLE:** Asset mesh deformation updates GPU/geometry state through revisions/events. Do not call `notifyUI()` on every `updateVertexDrag()` sample when selection/UI state did not change.

### 31. STATIC MESH SHELL DETECTION / COMPOSITION / HIERARCHY
- **USER-FACING TERM:** Use **Mesh Shell** for connected polygon geometry and reserve **UV Shell** for UV topology. Avoid bare `Shell` in Static Mesh hierarchy/Inspector labels where the distinction matters.
- **TOPOLOGY IS AUTHORITATIVE:** A Mesh Shell is a **vertex-connected** logical surface component. Resolve it from `LogicalMesh.faces` plus only explicit authored/imported `siblings`; faces that share even one actual/canonical topology vertex belong to the same Mesh Shell. Never trust `StaticMeshAsset.shells` metadata as count/membership truth.
- **NO POSITION-INFERRED WELDS:** Equal XYZ positions never prove connectivity. `LogicalMesh.siblings` must represent only explicit logical-weld identity (for example one OBJ position index split by UV/normal tuples). Two separate vertex IDs that merely occupy the same position remain separate shells unless an explicit sibling/weld relationship connects them.
- **BUILT-IN CUBE IS SIX MESH SHELLS:** Preserve the current 24-vertex Cube geometry. Its six quads do not share vertex IDs and it provides no explicit sibling groups, so it resolves as 6 Mesh Shells. Do not silently spatial-weld it back to one.
- **EXISTING WELDS MAY ONLY SPLIT DURING DEFORMATION:** At transaction finalization, an existing explicit sibling group may be partitioned when its members were edited apart. Rebuild propagated topology maps, invalidate connectivity, and rematerialize Mesh Shell metadata. Never create a new weld from proximity.
- **SAVED SHELL DATA IS METADATA/HINTS:** Range fields remain for compatibility/allocation provenance. New writes also persist exact logical face IDs (`faceIdsExact`) so non-contiguous Mesh Shells can be matched safely.
- **APPEND MUST PRESERVE, NOT INVENT, CONNECTIVITY:** Resolve source Mesh Shells from topology, offset/copy existing explicit sibling groups and provenance, then re-detect the final target. Never create cross-source sibling links because appended vertices overlap spatially.
- **IMPORTERS OWN TOPOLOGY IDENTITY:** OBJ import may derive sibling groups from shared OBJ source vertex indices, not XYZ. Future FBX import should preserve control-point and mesh-node identity. Separate source vertices/nodes remain separate even if positions match.
- **MESH SHELL IS A SELECTION SCOPE, NOT A COMPONENT MODE:** Keep `MeshComponentMode` as OBJECT/VERTEX/EDGE/FACE. A Mesh Shell row keeps `SHELL` as the user-facing hierarchy/Inspector context but internally uses VERTEX mode + all owned vertices so its gizmo transforms only that Mesh Shell. `Mesh Shell > Vertices/Edges/Faces` uses the same public component-mode/selection API for that shell set.
- **USE SHARED HIERARCHY ROWS:** Mesh Shells and their count rows must use `HierarchyTreeItem`; do not fork indentation/selection/expand behavior for Static Mesh parts.
- **INVALIDATE MEMOS FOR IN-PLACE ASSET UPDATES:** `AssetManager.updateAsset()` keeps object identity. Static Mesh hierarchy/inspector derivations must include `assetRevision` (or equivalent) so append and topology changes refresh counts immediately.
- **AUTO-REVEAL THE ACTIVE MESH SHELL:** When append or hierarchy selection chooses a Mesh Shell, expand `Geometry`, `Mesh Shells`, and that Mesh Shell row so its component summaries are visible.

- **SHIFT MULTI-SELECT MUST USE THE PUBLIC SELECTION OPERATION:** Hierarchy and viewport Shift-click use `setMeshComponents(..., operation: 'TOGGLE')`; do not mutate `subSelection` sets directly. Multi-Mesh-Shell selection is the union of component IDs owned by the selected shells.
- **GLOBAL COMPONENT ROWS MEAN SELECT ALL:** `Components > All Vertices/All Edges/All Faces` switches domain and selects every component in that domain. Toolbar/pie mode switches remain mode-only; do not conflate the two interactions.
- **PREVIEW ENTITY != ACTIONABLE SELECTION:** Static Mesh asset preview may keep/select its internal entity only as a component edit target. Opening the editor with no object/component selection must show no gizmo. Asset/Geometry hierarchy clicks explicitly opt into whole-object selection.
- **GIZMO CHECKS ONLY THE ACTIVE COMPONENT DOMAIN:** In VERTEX mode require selected vertices, in EDGE mode selected edges, and in FACE mode selected faces. Never let stale IDs from another domain pass the visibility guard and place a gizmo at `(0,0,0)`.

### 32. STATIC MESH AI CONSTRUCTION POINTS / SEMANTIC MODELING
- **CONSTRUCTION POINT != VERTEX:** `StaticMeshConstructionPoint` is a stable semantic/planning handle. `addPoint()` / `addPoints()` must never allocate `MeshGeometry` vertices just because a point exists.
- **SEMANTIC IDS OUTLIVE NUMERIC TOPOLOGY IDS:** AI/scripts should retain Construction Point/Face/Loop IDs returned by `StaticMeshAssetAPI`, not raw vertex/face/triangle array indices. Numeric topology IDs are compiled implementation details and may change after later topology work.
- **ONE POINT MAY BIND MANY VERTICES:** Keep `ConstructionPoint.vertexIds` one-to-many. UV seams, hard normals, material splits, or future topology edits may require multiple render vertices for one semantic location. `movePoint()` must propagate to every valid binding.
- **COMPILE INTO THE EXISTING TOPOLOGY:** Face/extrude/bridge operations must rebuild the normal `LogicalMesh`, half-edge graph, vertex-to-face map, normals, AABB, and topology-derived Mesh Shell metadata. Never create a parallel modeling-connectivity graph that disagrees with the Static Mesh topology system.
- **MUTATE THROUGH STATIC MESH API / ASSET MANAGER:** Construction changes belong in `StaticMeshAssetAPI` and commit through `assetManager.updateAsset()` so editor/scene invalidation follows the existing asset event flow.
- **POINT ORDER DEFINES FACE WINDING:** `createFaceFromPoints()` consumes an ordered polygon boundary. The current implementation is for planar, non-self-intersecting convex polygons and fan-triangulates them. Do not silently claim general concave n-gon support until a robust triangulator exists.
- **FACES OWN LOGICAL TOPOLOGY; SHARED POINT IDS MUST REUSE VERTICES:** `LogicalMesh.faces` is the authoritative logical surface. If two Construction Faces reference the same Construction Point, they must compile through the same valid mesh-vertex binding; an adjacent shared edge therefore uses the same two vertex IDs. Half-edge pairing additionally requires opposite winding along that shared edge. Do not duplicate vertices per face unless an explicit seam/split requires it.
- **DO NOT INVENT SIBLING FACES:** Ordinary face adjacency is derived from shared logical vertices/edges. `LogicalMesh.siblings` means explicit equivalence between duplicated render vertices, not a face-to-face relationship.
- **LOOPS ARE SEMANTIC HANDLES, NOT IMPLICIT GEOMETRY:** `createLoop()` records ordered point IDs only. The current `bridgeLoops()` requires equal point counts and matching open/closed state.
- **INSET PRESERVES FACE IDENTITY:** `insetFace()` must keep the selected Construction Face id (and its current logical `faceId`) as the new inner face. Build the border ring around the old boundary and return semantic inner-point/loop/border handles. Do not force AI/scripts to rediscover a replacement face after an inset.
- **FACE EXTRUDE CONSUMES THE SOURCE SURFACE:** `extrudeFace()` must move the selected Construction Face boundary onto the new offset points and create side faces around the old boundary. Do not leave a duplicate/source cap at the original location. Preserve the same semantic/logical face handle on the moved top surface (`topFaceId === sourceFaceId`) so AI/scripts can continue deterministically. An isolated plane therefore extrudes open; create an explicit bottom cap when a closed prism is desired.
- **FACE EXTRUDE IS NORMAL-DRIVEN:** Compute the current ordered Construction Face normal before mutation and offset every new top point by `normal * distance`. Positive distance follows the face normal and negative distance goes opposite. Do not silently use a world/ground axis and do not add an arbitrary direction override to `extrudeFace()`; a separate sweep/translate primitive should own that behavior.
- **GIZMO ACTIVATION IS UI-ONLY AFTER EXTRUDE:** The Static Mesh editor may switch to Move and show the translation gizmo after a successful UI Extrude so a modeller can continue adjusting the selected top face. `StaticMeshAssetAPI.extrudeFace()` itself must remain tool-neutral and must never activate editor gizmos for AI/script callers.
- **INSET FAILS BEFORE INVALID TOPOLOGY:** The current inset contract is constant world-space distance on ordered planar convex faces. Reject non-positive/oversized, non-planar, concave, zero-edge, or degenerate inputs instead of committing crossed/collapsed geometry.
- **SPLIT EDGE REUSES ONE SEMANTIC POINT ACROSS INCIDENT TOPOLOGY:** `splitEdge()` is addressed by Construction Point endpoint IDs, inserts one new Construction Point, and updates every incident authored face/loop to reuse it. Preserve stable face IDs/logical mappings and rebuild normal topology/history atomically. Raw mesh edge/vertex IDs are only an editor-selection adapter; do not make them the AI-facing identity. Reject endpoint positions outside `0 < t < 1` and non-manifold (>2 incident-face) edges before commit. Splitting inserts a collinear boundary vertex, so triangulation must avoid zero-area fan triangles; preserve the normal fan when valid, otherwise rotate/fall back to convex ear clipping.
- **CUT FACE COMPOSES EXISTING BOUNDARY POINTS:** `cutFace()` connects two existing non-adjacent Construction Points on one authored face. Keep the source semantic/logical face stable as one side, create exactly one new semantic face for the other, reuse endpoint vertices so the new diagonal half-edges pair, and rebuild topology/history atomically. Do not turn Cut Face into a hidden freehand knife/projection system: use `splitEdge()` first when a desired cut endpoint lies inside an edge. Reject adjacent/off-face/degenerate endpoint pairs before commit.
- **DELETE FACE PRESERVES SEMANTIC PLANNING DATA:** `deleteFace()` removes the authored Construction Face surface/triangles but keeps its Construction Points and Loops. Compact logical face ids, remap surviving Construction Face `faceId` values and `triangleToFaceIndex`, then rebuild normal topology/shell metadata in one history step. Do not leave sparse logical face arrays or silently garbage-collect planning handles.
- **TOPOLOGY UI MUST CALL THE SAME API:** Static Mesh dock Extrude/Inset/Delete Face/Split Edge/Cut Face actions dispatch through `EditorCommandRegistry` + the editor `topologyCommand` service into `StaticMeshAssetAPI`. Do not duplicate topology mutation logic in React. Working semantic face tools require exactly one selected logical face with an authored Construction Face mapping; Split Edge requires exactly one selected mesh edge that resolves to authored Construction Point endpoints; Cut Face requires exactly two non-adjacent selected Construction-backed vertices on exactly one common authored face. Unsupported imported/appended topology stays disabled rather than receiving invented Construction identity.
- **COMMAND AVAILABILITY IS HOST-SPECIFIC:** Use `supportsTopologyCommand(command)` when a shared command is not implemented by every host. In particular, keep semantic `INSET` disabled in Scene View until that host routes it through the Construction API; never expose a command that the host callback silently ignores.
- **KEEP CONSTRUCTION SELECTION SEPARATE:** Construction Points use a separate viewport VBO and selection domain. Do not stuff their IDs into mesh Vertex selection or show the normal component gizmo merely because a planning point is selected.
- **EMPTY CONSTRUCTION POINTS MUST STILL FRAME/RENDER:** An otherwise empty Static Mesh can contain planning points. Camera fit/focus and viewport overlays must work before any compiled mesh vertex exists.
- **TEST THE SEMANTIC CONTRACT:** Keep `npm run test:mesh-construction` covering point-without-vertex creation, face compilation, shared-face topology, point-to-bound-vertex movement, stable inset identity/ring pairing/collapse rejection, safe face deletion/remapping/undo, shared split-edge topology/loop updates/undo, cut-face stable identity/paired diagonal/undo, stable extrusion handles, deletion guards, Mesh Shell connectivity, UI command dispatch, and loop bridging.

### 18. STATIC MESH ASSET HISTORY / TRANSACTIONS
- **DO NOT USE SCENE ECS HISTORY FOR ASSET TOPOLOGY:** Static Mesh geometry/topology/Construction edits must use `engine/AssetHistory.ts`; Scene `HistorySystem` snapshots ECS state only.
- **ONE SEMANTIC ACTION = ONE ASSET TRANSACTION:** New Static Mesh API mutations should run through `assetHistory.execute(...)`. Multi-step AI/modeling intents must use `beginTransaction` / `commitTransaction` so Ctrl+Z does not expose internal implementation steps.
- **PRESERVE NON-JSON DATA:** Asset history snapshots must preserve typed arrays, `Map`, `Set`, and `ArrayBuffer` data. Never replace asset history with `JSON.stringify/parse` cloning.
- **LIVE DRAGS SNAPSHOT BEFORE MUTATION:** Component gizmo deformation mutates mesh geometry in place for preview, so the asset transaction must begin before the first live vertex mutation and commit once on mouse-up.
- **CTRL+Z MUST NOT TRIGGER PLAIN-Z ACTIONS:** In asset viewport key handlers, process Ctrl/Cmd history shortcuts before unmodified `Z` shortcuts such as wireframe.

### 28. STATIC MESH GIZMO / ASSET HISTORY SYNCHRONIZATION
- **GIZMO IS DERIVED UI:** Never store gizmo position, visibility, active axis, or hover axis as an AssetHistory snapshot. The mesh/selection are authoritative; derive the gizmo pivot from the live restored selection every render.
- **SELECT TOOL MUST NOT RENDER THE TRANSFORM GIZMO:** Static Mesh `SELECT` is selection-only. Keep `GizmoSystem.renderInSelectTool = false`; Object/Vertex/Edge/Face selection changes may preserve an already active MOVE/ROTATE/SCALE tool, but must never activate a transform tool or make the gizmo appear by themselves.
- **ONE DRAG = ONE ASSET TRANSACTION:** Begin Static Mesh component history at gizmo drag start, mutate geometry live, and commit once on mouse-up. A zero-total-delta drag must close cleanly without creating Undo history.
- **CANCEL UNFINISHED DRAGS:** `Esc` cancels an active component drag back to its drag-start state with no history entry. `Ctrl/Cmd+Z` during an unfinished drag cancels that drag first; do not consume the previous committed history step in the same key press.
- **PRESERVE VALID SELECTION THROUGH HISTORY:** Undo/Redo must not blindly clear Vertex/Edge/Face, Construction Point, or Mesh Shell selection. Preserve ids that still exist in the restored asset and prune only stale ids, then recompute soft-selection weights.
- **RESET TRANSIENT GIZMO STATE AFTER RESTORE:** Clear active/hover handle state after Undo/Redo so the next render recomputes the gizmo from restored geometry. Never restore a cached gizmo transform.
- **DO NOT CLOSE SOMEONE ELSE'S TRANSACTION:** If a gizmo drag starts inside an already-open semantic asset transaction, the drag does not own that outer transaction. Commit may mark it dirty but must not close it; cancel restores only the drag-local geometry baseline.
- **NARROW GENERIC ASSETS BEFORE MESH-ONLY ACCESS:** `assetManager.getAsset()` returns the generic `Asset` contract. A runtime `asset.type === 'MESH'` check does not currently make TypeScript infer `StaticMeshAsset`; after the guard, narrow once to a typed `StaticMeshAsset` local before calling shell helpers or reading typed Construction data. Do not let mesh-only restore code fall back to implicit `any`.

### 33. STATIC MESH MANUAL TEST FIXTURES
- **USE `smTest()` FOR REPEATABLE RUNTIME SETUP:** Manual browser/editor checks should recreate deterministic `TEST_StaticMesh_*` fixtures through `engine/dev/StaticMeshTestFixtures.ts`, not by copying long ad-hoc console scripts after every restart.
- **DO NOT ACCUMULATE THROWAWAY FIXTURES:** Creating a fixture removes only earlier `TEST_StaticMesh_*` assets first. Never delete arbitrary/user-authored meshes as part of test reset.
- **FIXTURES MUST USE THE PUBLIC MODELING API:** Test setup calls `StaticMeshAssetAPI` primitives so it exercises the same Construction/topology code as AI and UI. Do not hand-write geometry/topology arrays in the fixture helper.
- **CLEAR HISTORY AFTER FIXTURE SETUP:** A generated fixture is the baseline, not a user edit. Clear its AssetHistory after construction so the next manual operation is the first Undo step.
- **KEEP A SPLIT-READY FIXTURE:** `smTest('split')` must build two authored triangles sharing one edge (plus a semantic loop) through the public API so Edge-mode Split Edge can be retested quickly after restart.
- **KEEP A CUT-READY FIXTURE:** `smTest('cut')` must build one authored quad through the public API and expose opposite Construction Point ids so Vertex-mode Cut Face can be retested quickly after restart.

- **TOPOLOGY VALIDATION IS USER FEEDBACK, NOT A CONSOLE FAULT:** Keep modeling APIs strict/atomic, but catch expected UI validation failures (for example an oversized inset) at the Static Mesh editor boundary and show the API message inline. Do not silently clamp values, commit partial topology/history, or spam console error stacks for safe user-input rejection.

### 28. STATIC MESH QUAD TOPOLOGY QUERIES / EDGE RINGS
- **LOGICAL FACES, NOT RENDER TRIANGLES:** Quad detection and opposite-edge traversal must use `LogicalMesh.faces`. Never infer a quad from pairs of render triangles at query time; triangulation diagonals are not authored edges.
- **CANONICAL EDGE IDENTITY:** Edge adjacency/ring traversal must use `MeshConnectivity` canonical/sibling identity so explicit UV/normal seam welds can continue a ring. Equal XYZ positions alone never connect edges or faces.
- **RING != LOOP:** Edge Ring walks across the opposite edge of each quad. Edge Loop follows edge flow through vertices. Do not merge these algorithms or choose the next edge by geometric straightness alone.
- **STOP EXPLICITLY:** Read-only ring traces must report termination (`BOUNDARY`, `NON_QUAD`, `BRANCH`, `CYCLE`, `INVALID_TOPOLOGY`, `MAX_STEPS`) instead of silently jumping across triangles/ngons/non-manifold branches.
- **QUERY BEFORE MUTATION:** Face classification, opposite-edge lookup, Edge Ring and Quad Strip are read-only. They must not create Asset History entries, mutate Construction identity, or rebuild geometry.
- **SHARED API FOR UI/AI:** Static Mesh editor Edge Ring / Quad Strip selection must call the shared topology query API. Never implement a second React-only traversal.

### 32. ASSET EDITOR WINDOW LIFETIME
- **ASSET EDITORS MUST DECLARE `assetId`:** Every asset-backed `AssetEditorWindowConfig` must carry the UUID of the asset it edits. Do not rely only on an `editor_<uuid>` naming convention for lifecycle cleanup.
- **DELETE CLOSES THE EDITOR:** `WindowManager` must remove windows whose `assetId` matches an `ASSET_DELETED` event. Never leave an asset editor mounted against a deleted UUID; it produces stale `Mesh asset could not be loaded.` windows and retains unnecessary viewport/editor state.
- **DEV FIXTURES USE THE SAME RULE:** `smTest(...)` intentionally deletes older `TEST_StaticMesh_*` fixtures before creating a new one. Open fixture editors must therefore close through the normal asset-deletion lifecycle, not through special coupling from engine test-fixture code to React/UI code.

### 18. STATIC MESH FACE HOVER / SELECTION FILL
- **FACE MODE NEEDS SURFACE FEEDBACK:** Do not render Face selection as boundary edges only. Static Mesh Face mode must keep a subtle translucent fill for hovered and selected logical faces so the interaction target reads as a surface.
- **LOGICAL FACE IDENTITY:** Build face-fill triangle indices from `LogicalMesh.triangleToFaceIndex`; never treat each render triangle of a quad/ngon as an independent face highlight.
- **VISUALIZATION ONLY:** Face fill must not mutate geometry, topology, materials, selection identity, or history. It reuses the host position VBO and owns only a compact overlay IBO.
- **DEPTH SAFETY:** Keep depth testing enabled, use `LEQUAL`, disable depth writes, and use a small negative polygon offset so front-facing fills do not z-fight while back-side faces remain hidden.
- **NO DOUBLE-BRIGHT HOVER:** If a hovered face is already selected, suppress the separate hover fill and keep the selected fill as the authoritative visual state.

- **BEVEL IS A SMALL SEMANTIC PRIMITIVE:** `bevelEdge()` is addressed by stable Construction Point endpoint ids, not raw mesh edge ids. The selected edge requires exactly two consistently wound non-coplanar authored faces, but endpoint valence is not capped at three. Resolve a unique interior manifold endpoint fan, propagate one offset point along every participating one-ring edge, and add an endpoint cap polygon when three or more offsets are required. Reject open/branched/disconnected/non-manifold high-valence fans and too-large widths atomically rather than guessing topology.
- **PROPAGATE BEVEL OFFSETS THROUGH AUTHORED BOUNDARIES:** When Bevel creates offset points on neighboring edges, insert those same semantic points into every authored face/loop using those edges. Rewrite endpoint faces around the new points and compact orphan render vertices while preserving source Construction Points as semantic handles.
- **DO NOT RESTORE THE OLD CLOSED-PRISM EXTRUDE:** Face Extrude no longer keeps/reverses the original face as a bottom cap. The source semantic/logical face is moved to the new top boundary and side walls are added. Closed test fixtures that begin from an isolated plane must add a separate reversed bottom face explicitly; extruding a face on an existing manifold mesh remains connected through its neighboring faces.

### 34. SEARCHABLE STATIC MESH TEST REPORTS
- **KEEP THE NORMAL TEST SEARCHABLE:** `npm run test:mesh-construction` must tee the real construction-test stdout/stderr into `reports/static-mesh-construction-test.txt` while preserving the child process exit code. Do not replace the actual test with a synthetic summary.
- **VS CODE OPENING IS OPTIONAL UI CONVENIENCE:** `npm run test:mesh-construction:open` may reopen the latest report with VS Code, but failure to locate VS Code must never turn a passing mesh test into a failure. Always print the report path as fallback.
- **DO NOT COMMIT GENERATED REPORTS:** Keep `reports/*.txt` ignored. The stable filename is intentional so developers can search one predictable file after repeated runs without accumulating timestamped artifacts.
